# 第30章作业 (threads-bugs)

## 第1题：./vector-deadlock -d -n 2 -l 1 -v
预测：使用 -d 参数开启死锁模式。两个线程以相反的顺序获取锁（线程0先获取0再获取1，线程1先获取1再获取0），会导致死锁。
核对：运行结果：
- 线程 0 执行 ->add(0, 1) 和 <-add(0, 1)
- 线程 1 执行 ->add(1, 0) 和 <-add(1, 0)
- 由于两个线程以不同顺序获取锁，程序在运行中可能会死锁。
- 注意：输出中显示两个线程都完成了操作，说明这次运气好没有死锁，但在高并发下死锁概率很高。
## 第2题：./vector-global-order -d -n 2 -l 1 -v
预测：使用全局锁顺序（按向量地址排序）来避免死锁。即使线程以不同顺序调用 add，也会按地址顺序获取锁。
核对：运行结果：
- 线程 0 执行 ->add(0, 1) 和 <-add(0, 1)
- 线程 1 执行 ->add(1, 0) 和 <-add(1, 0)
- 由于按全局顺序获取锁，不会发生死锁。
## 第3题：./vector-try-wait -d -n 2 -l 1 -v
预测：使用 pthread_mutex_trylock() 尝试获取锁。如果获取失败，就释放已持有的锁，然后重试。
核对：运行结果：
- 线程 1 先执行 ->add(1, 0) 和 <-add(1, 0)
- 线程 0 执行 ->add(0, 1) 和 <-add(0, 1)
- Retries: 0（表示没有发生重试，因为这次运行没有发生锁冲突）
## 第4题：./vector-avoid-hold-and-wait -d -n 2 -l 1 -v
预测：使用一个全局锁来避免持有并等待（hold-and-wait），即先获取全局锁，再获取向量锁。
核对：运行结果：
- 线程 0 执行 ->add(0, 1) 和 <-add(0, 1)
- 线程 1 执行 ->add(1, 0) 和 <-add(1, 0)
- 通过全局锁保证不会发生死锁。
## 第5题：./vector-nolock -d -n 2 -l 1 -v
预测：不使用锁，而是使用原子 fetch-and-add 操作来实现 vector_add()。没有死锁风险。
核对：运行结果：
- 线程 0 执行 ->add(0, 1) 和 <-add(0, 1)
- 线程 1 执行 ->add(1, 0) 和 <-add(1, 0)
- 因为没有使用锁，所以不会死锁。原子操作保证了数据一致性。
